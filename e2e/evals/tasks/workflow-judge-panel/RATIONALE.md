# workflow-judge-panel

**Measures.** A judge panel: three independent judges score two
candidates against a spec, a chair tallies. The fan-and-merge shape with
a ground truth: candidate `a` fails a case the spec names (a cut that
ends on a hyphen), so the panel's verdict has a right answer.

**Converts.** New; the shape predicate is the gallery's
`fan_join?` (`shapes.rb:101-115`) on the compose door, and on the task
door the fan that came back whole (`Predicates.fan_completed`: every
task the fan raised completed, every loop completed — waited or
detached alike). A fan-and-merge owes no receipt: a judge called with
`wait: true` returns inline and the kernel mails nothing, so the
receipt-wake loop is the iterative shapes' pass (adversarial-verify,
loop-until-dry), not this task's. Requiring mail here would wrongly reject
a completed waited fan whose verdict passes the oracle. The oracle is re-run by the
verification.

**Dimensions.** reach = a door; success = the shape AND the reply names
`b`; task pass = `verdict.md` names b with the oracle holding; `door`,
`loop_style` (the receipts among them), `waited`, `judges` are facts.

## Reading a red

- **lane bug** — `error`, or the deadline before a round settled; a
  verification output saying "oracle false" (the fixture, not the model).
- **model conduct** — "no compose call and no round fanned two task
  calls" (it judged itself); "r1t0 composed 4 tasks and no step reads
  two model members" (judges in sequence, no chair); "the reply does not
  name b as the winner".
- **kernel finding** — "the merge step … did not complete"; "… did not
  complete: the fan never came back whole" (a judge the kernel never
  settled); a loop that never completed on the feed.
